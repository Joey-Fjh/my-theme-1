## Batch H6: client-neutral harness core with per-client hook adapters

**Status:** executed and reviewed (2026-10-21): Ask review PASS in round 2. Replaces the uncommitted H6-cursor and H6-codex attempts, which ran in this worktree at the same time and are not reviewed.

**Why.** The first attempt used Claude Code's hook format as the shared language: `cursor-hook.mjs` renames Cursor tools to Claude names (`StrReplace`/`Delete` → `Write`, `Shell` → `Bash`) before calling `handlePre`, and both adapters parse Claude's `hookSpecificOutput.permissionDecision` back out; each adapter also has its own stdin decoder and fail-closed wrapper (only Cursor's strips a BOM). The cause was the coordinator's prompt ("translates … to and from the existing hook.mjs functions"). Direction (user, 2026-10-21): the harness is a client-neutral abstraction; each client gets its own hook file in its own directory that adapts to it, the way each client reads skills or MCP in its own format.

**Outcome.** One core holds every decision in domain terms and has no client field names. Each client has a config plus a thin adapter in its own directory that maps its events and payload to the core and the core's decisions back to its output. Claude Code behaviour is unchanged.

**Design.**
- `.agents/tools/harness/core.mjs` (rename of `hook.mjs`'s logic, not a copy): `checkWrite(root, paths, addedText)`, `checkShell(root, command)`, `checkSubagent()` return `{ decision: 'allow' | 'ask' | 'deny', reason }`; `routeHints(root, session, paths, addedText)` and `planContext(root, session)` return text; `stopCheck(root, session)` returns `{ failures, notice }`; `readInput()` decodes stdin (UTF-8 BOM, UTF-16 LE/BE by BOM or NUL bytes, empty, malformed); `runAdapter(event, isGuard, fn)` gives every adapter the same fail-closed behaviour (guard events deny on any error, others no-op). Session state, routes and merchant data stay as today (`routes.json`, the state file).
- `.claude/claude-hook.mjs`: Claude events → core; `ask` stays `ask`. `.claude/settings.json` commands point to it.
- `.cursor/cursor-hook.mjs` + `.cursor/hooks.json`: Cursor events → core; `ask` → `deny` where Cursor does not enforce it (`preToolUse`, `subagentStart`), kept on `beforeShellExecution`; workspace root `/d:/…` normalised; plan context at `sessionStart`; stop failures as one `followup_message` (`loop_limit` 1).
- `.codex/codex-hook.mjs` + `.codex/config.toml` hooks: Codex events → core; `apply_patch` Add/Update/Delete/Move targets → `checkWrite`; `ask` → `deny`. The command must resolve the adapter on Windows (verify which shell runs `command_windows` and whether `$(git rev-parse --show-toplevel)` expands there; otherwise use a form that does).
- Adapters contain only mapping: no path globbing, merchant lists, route matching, push detection, or record checks.

**Facts carried from the first attempt** (official docs via Context7 and the vendor sites, plus live captures; condensed here, the first attempt's records were never committed):
- Cursor (docs `cursor.com/docs/hooks`, Cursor 3.26.13): project config `.cursor/hooks.json`; hooks are cached and reload on save, so deleting or renaming the file leaves the last config active — saving `{"version":1,"hooks":{}}` unloads them. Stdin is UTF-8 with a BOM (`efbbbf7b22636f6e…`), no `cwd`, `workspace_roots` like `/d:/fjh/shopify/my-theme-1`. `preToolUse` accepts `ask` but does not enforce it; `beforeShellExecution` enforces `ask`; `beforeSubmitPrompt` cannot add context; `afterFileEdit` cannot block or add context; `stop` can only continue the turn via `followup_message`. `failClosed` blocks on crash, timeout, non-zero exit or no output.
- Codex (docs `developers.openai.com/en-US/docs/hooks` and the config reference, Codex CLI 0.162): project hooks in `.codex/config.toml` `[hooks]` or `.codex/hooks.json`; events `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`; shell appears as `Bash`, edits as `apply_patch` with patch text in `tool_input.command`; no `ask` (reported as a hook failure and the tool runs), so deny; callback errors can fail open; `Stop` `decision: "block"` continues the turn.
