1. **Dynamic class detection, tightened.** A file counts as a dynamic builder of class `c` only if it contains a prefix of `c` that ends at a BEM boundary (`__` or `--`) or is `c`'s full block name followed by `-`, immediately followed by `{{`, `{%`, or a closing quote used in `append`/`prepend`/`|` concatenation; list every dynamic hit with file and line in the record, and treat a hit as real only after reading it.
2. **`tailwind.snippets.css` is removed.** Rules that pass ownership move to their owner. Rules that stay shared move into `tailwind/tailwind.components.css`. Delete the file and its `@import`.
3. **`tailwind.animates.css`.** `@utility` definitions stay (they are utilities, generated only when markup uses them). Global motion (`body[data-motion-*]`, `[data-motion-*]`, reduced-motion rules) stays. A rule or `@keyframes` used by one owner only (ownership rule above; for a keyframe, every rule that references it in its `animation`/`animation-name` must move to the same owner, or it stays) moves to that owner's `{% stylesheet %}` with its layer context (unlayered stays unlayered).
4. **`tailwind.elements.css`.** Native element and field/button base styles used across files stay. Single-owner rules move under the ownership rule.
5. **Lint-blocked rules.** A rule whose compiled form fails `lint:theme` or `lint:compat` inside `{% stylesheet %}` stays in the build unchanged (as in 5-C1); list it.
6. **Dead rules.** Delete only with no consumer anywhere (Liquid incl. tightened dynamic check, `assets/*.js`, schema, config, templates JSON, section groups); list evidence.

### Review round 1 (independent reviewer, 2026-10-02): FAIL, ownership of nested and generated classes, and fix

- Findings: seven moved rules required shared classes only inside nested selectors (`.icons`, `.is-active` in `snippets/product-gallery-thumbnails.liquid`; `.rte` in `snippets/product-info-blocks.liquid`) or classes Swiper generates at runtime (`.swiper-pagination-bullet`, `-active` in `sections/icon-with-text.liquid`). Static and browser parity were otherwise clean.
- Fixes to the tool: (1) classes required by nested selectors must also be exclusive to the owner; (2) a class counts as exclusive only if it appears in Liquid markup and no theme JS references it (JS-built or vendor-generated classes are shared); (3) **block atomicity**: if any rule of a BEM block stays in the build, every rule of that block stays. Rule (3) came from a stable browser-parity failure of the intermediate run: `.product-info-blocks--product .product-info-blocks__description { max-width: 46ch }` moved while `.product-info-blocks--gallery .product-info-blocks__description { max-width: none }` stayed (nested `.rte`), and the description carries both modifiers, so the moved rule now loaded later and won (`max-width` none → 462.875 px, gallery 5,400 px taller).
- Result, rerun from `HEAD`: **20 rules move into 4 owners** (`snippets/product-purchase-stack.liquid` 9, `snippets/product-quick-view.liquid` 8, `snippets/search-predictive-panel.liquid` 2, `snippets/product-card.liquid` 1). Blocks kept whole in the build: `product-info-blocks`, `icon-with-text-section`, `icon-with-text-item`, `product-quick-view-dialog`, `watermark-marquee`, `scrolling-icon-with-text` (67 rules). `tailwind/tailwind.animates.css` and `tailwind/tailwind.elements.css` end unchanged. `tailwind/tailwind.snippets.css` is still deleted, its remainder appended to `tailwind/tailwind.components.css` inside `@layer snippets`.
- Checks: static parity 1,648 → 1,648, no differences; `lint:theme`, `lint:compat` (54 blocks), `lint:liquid-syntax`, `lint:i18n`, `lint:doc-paths`, `test:theme-check` (142 files, no offenses), Prettier: pass; 4 Liquid files changed, only inside `{% stylesheet %}`.
