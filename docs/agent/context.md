**Outcome.** Component-owned CSS lives in its owner's `{% stylesheet %}`, so Shopify's stylesheet subsetting loads it only on pages that render that owner; the Tailwind build keeps only shared vocabulary; dead classes and file-encoding damage are gone; **the storefront renders exactly as before**.

**Background (measured 2026-10-02).** `tailwind/tailwind.snippets.css`: 1,798 lines, 24 `Owner:` blocks in `@layer snippets`, 140 of 175 classes used by one Liquid file, 205 `@apply`. `tailwind/tailwind.components.css`: `@layer components`, 47 of 105 classes used by one Liquid file, 92 `@apply`. 16 classes with no literal consumer. BOM and garbled comments (broken encoding, e.g. `鈥?` for an em dash) in `tailwind.snippets.css`, `tailwind.components.css`, `tailwind.elements.css`. Load order: `layout/theme.liquid` loads `assets/tailwind.output.css` before `content_for_header` (which carries Shopify's `styles.css` from `{% stylesheet %}`); `tailwind/tailwind.input.css` declares `@layer theme, base, components, snippets, utilities;`.

**Rules.**

1. **Cascade preserved.** Unlayered CSS beats every layer, so moved rules keep their origin layer: wrap them in `@layer snippets { … }` or `@layer components { … }` inside the `{% stylesheet %}` (native CSS; the order is already declared by `tailwind.output.css`, which loads first). If `lint:theme` or `lint:compat` rejects `@layer` in a `{% stylesheet %}` block, stop and report: validators are user-owned.
2. **Plain CSS only** in `{% stylesheet %}`: every `@apply` becomes the CSS that utility generates in `assets/tailwind.output.css` (copy its declarations, including `var(--spacing)` and token forms, custom `@utility` bodies such as `focus-ring`, and variants as nested `&:hover`, `@media`, etc.). No Liquid inside the block; one block per file (append to an existing block).
3. **Owner choice (subsetting).** A class moves into file F only if every file that uses it is F or a file F directly renders (`{% render %}` / `{% section %}`), and the class is not added by JavaScript to elements outside that tree. Classes used by two unrelated files, or added by `assets/*.js` outside the tree, stay in the Tailwind build (in `tailwind.components.css` if they came from `tailwind.snippets.css`). Count consumers in Liquid markup, Alpine `:class` / `x-bind:class` expressions, and `assets/*.js` (`classList`, class strings).
4. **Dead classes.** Delete a class only when no consumer exists anywhere: Liquid (including built names like `swatch--{{ shape }}`, `{{ prefix }}__x`), `assets/*.js`, `{% schema %}` option values, `config/settings_schema.json`, and values in `templates/*.json`, `sections/*-group.json`, `config/settings_data.json` (read only). If a dynamic build could produce it, keep it. List each deletion with its search evidence.
5. **Encoding.** Remove BOMs; restore garbled comment text (comments only) from its meaning or `git log -p`; files UTF-8 without BOM, LF.
6. **Shared layers stay shared.** If `tailwind/tailwind.snippets.css` ends empty, delete it and its `@import` in `tailwind/tailwind.input.css`; otherwise list each remaining block with the reason it stays.
7. **No markup change.** Liquid outside `{% stylesheet %}` blocks, JS, schema, and locales do not change.

**Implementation surface.** `tailwind/tailwind.snippets.css`, `tailwind/tailwind.components.css`, `tailwind/tailwind.elements.css` (encoding only), `tailwind/tailwind.input.css` (the `@import` line only), `{% stylesheet %}` blocks in `sections/*.liquid` and `snippets/*.liquid` (add or append), `assets/tailwind.output.css` (regenerated by `npm.cmd run build:tw`, never hand-edited). Forbidden: everything else, including Liquid markup, `{% schema %}`, `assets/*.js`, `assets/base.css`, `config/*`, `templates/*.json`, `sections/*-group.json`, locales, the agent rules, references, and validator wiring. A needed change outside the surface: stop and list it.

**Method.** (1) Encoding: BOM removed; the garbled sequences decode as `鈥?` = "— " and `鈫?` = "→ " (the third UTF-8 byte swallowed the following space), restored in comments only; rebuilt `assets/tailwind.output.css` was byte-identical to `HEAD`. (2) Ownership per leaf rule: for each comma part of the selector, the classes it requires (not those inside `:not`/`:is`/`:where`/`:has`); a class's consumers are the Liquid files whose markup (outside `{% stylesheet %}` and `{% schema %}`) contains it, including dynamic builds (`'prefix--' | append`, `prefix--{{`); the owner is a file whose direct render tree contains every consumer of a required class in every part. (3) Moved rules are removed from the Tailwind sources, the build is rerun, and the rules that left the compiled output are copied **from the compiled output** (so `@apply` is already expanded by Tailwind itself) into the owner's `{% stylesheet %}`, wrapped in their origin `@layer` and media context. (4) Prettier on the changed files.
