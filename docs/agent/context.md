### Design

- **Steps** (`--spacing-step-*` in `@theme inline`, so `gap-step-m`, `mt-step-l`, `px-step-s` exist for every spacing property): Utopia-style multipliers of one base, 6px at 375px to 10px at 1280px (the 0.6× fluid rule the aliases already use):

| Step | × base | 375px | 1280px |
| --- | --- | --- | --- |
| `step-3xs` | 0.25 | 1.5px | 2.5px |
| `step-2xs` | 0.5 | 3px | 5px |
| `step-xs` | 0.75 | 4.5px | 7.5px |
| `step-s` | 1 | 6px | 10px |
| `step-m` | 1.5 | 9px | 15px |
| `step-l` | 2 | 12px | 20px |
| `step-xl` | 3 | 18px | 30px |
| `step-2xl` | 4 | 24px | 40px |
| `step-3xl` | 6 | 36px | 60px |

- **Why the `step-` prefix:** a bare `--spacing-xl` / `--spacing-2xl` makes Tailwind resolve `max-w-xl` / `max-w-2xl` to the spacing value instead of the container width (proved with a test build); `slides-show` uses both.
- **Aliases** (`--spacing-<name>: var(--spacing-step-…)`, utilities generated by Tailwind): `tight` = `2xs`, `related` = `s`, `group` = `m` (identical to today's values), and new `section` = `xl` (header group to body inside a section; value provisional, calibrated with the design).
- **Old-to-new table** for the polish pass (raw Tailwind spacing unit is 2.5px on the 62.5% root): `1`→`3xs`, `2`→`2xs`, `3`→`xs`, `4`→`s`, `5`→`m`, `6`→`m`, `8`→`l`, `10`→`xl`, `12`→`xl`, `16`→`2xl`, `20`→`3xl`, `24`→`3xl`; larger values and positioning offsets (`inset`, `top`, …) are named exceptions. Old raw values are fixed; the steps are fluid, so mobile spacing shrinks to 0.6× when a raw value migrates (a visual change owned by the polish pass).
- **Note for 6-C7 to 6-C9 (6-C6 parked):** new or changed markup adds no utilities to elements with their own stylesheet class.
