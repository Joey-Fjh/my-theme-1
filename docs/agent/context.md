### Evidence (read 2026-10-13)

- **Menu.** `snippets/header-dropdown-menu.liquid` (two summaries) and `snippets/header-dropdown-super-menu.liquid` (one summary) bind `:aria-expanded="$el.parentElement.open"`. `assets/dropdown.js` opens with `setAttribute('open', '')`, a DOM attribute Alpine does not track, so the binding is evaluated once and stays `false`. `snippets/sort-by-dropdown.liquid` binds `Boolean(openEls[0])`, which is reactive state; it passed the smoke pass and is not touched.
- **Spinner.** `snippets/loading.liquid` and `snippets/buy-buttons.liquid` use `animate-spin`. `tailwind/tailwind.input.css` resets `--animate-*: initial`, so no `.animate-spin` rule is generated. `docs/references/style-system/css-architecture.md` already says not to use `animate-spin` and to use the `.spinner` recipe in `tailwind/tailwind.animates.css`, which has no consumer.
- **Recipe timing.** `.spinner` runs `spinner-turn var(--motion-duration-base) var(--motion-ease) infinite`, which resolves to 400ms with `cubic-bezier(0.22, 1, 0.36, 1)`: a turn that decelerates to a stop every 400ms. That is a transition timing, not a continuous indicator.
- **Recipe and utilities.** The recipe sets `border: 2px solid currentColor; border-top-color: transparent`. A `border-*` colour utility on the same element would repaint the top edge and hide the rotation, so colour must come from `currentColor`. No caller passes `spinner_color` (`render 'loading'` has five callers; none sets it).

### review-animations (check 9)

Scope: the one motion change, the `spinner` recipe in `tailwind/tailwind.animates.css`.

| Before | After | Why |
| --- | --- | --- |
| `animate-spin` on both indicators (no rule generated, so no motion) | `spinner` recipe | A loading indicator that does not move gives no state indication (standard 1). |
| `spinner-turn var(--motion-duration-base) var(--motion-ease) infinite` (400ms, `cubic-bezier(0.22, 1, 0.36, 1)`) | `spinner-turn 0.8s linear infinite` | Constant motion takes `linear` (STANDARDS, Easing); an ease-out curve on an infinite turn stops and restarts every cycle. |

Verdict:

- **Performance:** `transform` only. No finding.
- **Interruptibility:** keyframes are right for a constant loop that is never retargeted. No finding.
- **Accessibility:** `prefers-reduced-motion: reduce` sets `animation: none; opacity: 0.65` (unchanged). The standard asks for gentler motion, not zero; a still ring signals loading weakly. Not a regression of this batch, since before it the ring never moved for anyone. Left for the polish pass (for example an opacity pulse).
- **Decision:** Approve.
