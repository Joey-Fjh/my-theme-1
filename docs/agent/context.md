## Plan 6-C5: page frame (width and screen height)

**Status:** **authorized** (user, 2026-10-09), executed from an external execution prompt. Review tier: **Ask** (validator wiring, Liquid in sections and snippets). Base: plan 6-F1 (`git show c0e9bcb:docs/agent/context.md`), accepted in full by the user 2026-10-09 with its two deviations and additions (a) to (c).

### Outcome

The page frame becomes the single owner of page width and the one-screen height unit. Inner layers consume what the frame provides and never recompute it. **Nothing on the storefront moves:** every computed column and content box is identical before and after. Visual tuning belongs to calibration and the polish pass.

### Why

- The frame had the mechanism (`container-page`, `section-frame` `width`, height kinds) but no owner rule. Sections recomputed the page inset (`ritual-steps`), four sections and `product` write their own screen heights, and the same three-track grid is defined twice. Each gap let a section break the page margins unnoticed.
- Layers like the JS module graph: tokens → page frame → section frame → section interior. The interior's grid or flex is the section's own business; width and the one-screen unit are not.
- Enforced only where a rule is cheap to check and has few legitimate exceptions; the rest is guidance.
- Experience consulted, not authority: the breakout grid with named lines (Ryan Mulligan, Josh Comeau), CUBE CSS and Every Layout (parent-owned composition, named exceptions, content-growing covers). The background-only `full` rule is our own decision (user, 2026-10-07).

### Rules this batch establishes

| Rule | Kind | Check |
| --- | --- | --- |
| One page-grid track list with named lines `full` / `content`, used by `.shopify-section` and `container-page` | Enforced by structure | A1 |
| Liquid files (`sections/`, `snippets/`) never read `--page-width` / `--page-margin`; custom insets use the frame token `--page-inset` | **Enforced** (`lint:theme` `page-token-scope`) | A3, A5 |
| `tailwind/tailwind.components.css` never reads `--page-width`; `--page-margin` stays readable there as the gutter token (addition b) | **Enforced** (same rule) | A3, A5 |
| A one-screen height is `var(--screen-height)`, never a literal `100svh` / `100vh` / `100lvh` / `100dvh` as a page height in Liquid files; overlay caps (`header` menu `100dvh` minus bars) are named exceptions | **Enforced** (`lint:theme` `screen-height-literal`) | A4, A5 |
| `section-frame` `width: 'full'` only in allowlisted sections, each with a reason | **Enforced** (`lint:theme` `frame-full-allowlist`) | A5 |
| Full-width sections keep text and controls on the `content` column; only backgrounds and named media span | Guidance + verifier prompt | A6 |
| Fractional viewport units inside a section's own choreography (`ritual-steps` offsets), overlay `dvh` / `vh` caps, the `article` / `search` heroes and the `product` 80 / 90svh options stay section or overlay business | Guidance (deviation 1) | — |
| Section height defaults to content; screen heights only for hero, scroll stages and media-led two-column sections | Guidance | — |

**`full` allowlist:** `slides-show` (slide media behind content), `routine-showcase` (stage background), `article`, `blog` (hero media behind content), `main-page-about` (image behind content), `ritual-steps` (stage background; content inset by `--page-inset`), `promo-bannder` (edge-to-edge panel media; text alignment checked in the polish pass), `google-map` (the map is the content; named exception).

### Implementation surface

- `assets/base.css`: frame tokens on `:root`, defined once: `--page-grid-columns` (named lines, today's tracks) and `--page-inset` (`max(var(--page-margin), calc((100% - var(--page-width)) / 2))`); `.shopify-section` uses them; children default to `grid-column: content`, `.full-width` to `grid-column: full`.
- `tailwind/tailwind.utilities.css`: `container-page` uses `--page-grid-columns` and `grid-column: content`.
- `tailwind/tailwind.input.css`: `--screen-height: 100svh`; `--section-stage-min-height: var(--screen-height)`.
- `assets/tailwind.output.css`: regenerated by `npm.cmd run build:tw` only.
- `sections/ritual-steps.liquid` (`{% stylesheet %}` only): the two inset formulas → `var(--page-inset)`; one-screen `100svh` → `var(--screen-height)` (fractional offsets stay).
- `sections/featured-product.liquid`, `sections/promo-bannder.liquid`, `sections/routine-showcase.liquid` (`{% stylesheet %}` only): `100svh` → `var(--screen-height)` inside the existing formulas; values unchanged (deviation 2).
- `sections/product.liquid`: `desktop_media_max_height` value `'100svh'` → `'var(--screen-height)'`.
- `snippets/grid-feature-card.liquid` (addition a): `sizes` rewritten with literal lengths only (no `var()`), the same breakpoints and column intent as today's intended value (2 columns below 768px, 4 above, page width 1440px).
- `.agents/skills/check-theme-architecture/scripts/lint-theme.js` and a new `lib/` module if the rules live there: `page-token-scope`, `screen-height-literal`, `frame-full-allowlist`.
- `.agents/skills/check-theme-architecture/scripts/theme-architecture.test.js`: one pass and one fail case per rule.
- `.agents/skills/check-theme-architecture/SKILL.md`: rule list.
- `docs/references/style-system/css-architecture.md`, Page frame section: layer order and ownership, the tokens, the rules table (enforced vs guidance), the allowlist; Height kinds: `--section-stage-min-height` via `--screen-height`.
