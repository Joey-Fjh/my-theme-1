**Implementation surface and method.**

1. R1 newsletter feedback.
    - `sections/newsletter-banner.liquid`: inside the form, `form.posted_successfully?` renders a `role="status"` message (`newsletter.success_message`); `form.errors` renders a `role="alert"` message (`form.errors | default_errors`) linked to the email input by `aria-describedby`, with `aria-invalid="true"` on the input. `assets/newsletter-banner.js` stops calling the toast for the banner (the inline message replaces it; the shared `toastNewsletterPostedSuccess` helper stays for the overlay).
    - `sections/newsletter-overlay.liquid` and `assets/newsletter-overlay.js`: the same inline error inside the overlay form, using the existing `error_message` setting with `form.errors | default_errors` as detail; when the overlay form has errors, the overlay opens on load regardless of its delay and visitor rules (a data attribute from Liquid) with focus on the email input. Success keeps the current toast and the expired flag.
    - Locale keys only if a new string is needed (`lint:i18n`).
2. R2 countdown date. `sections/promotion-countdown.liquid` passes the end time as a number (`section.settings.end_date | date: '%s'`); `assets/countdown-timer.js` reads it as epoch seconds and treats a non-number as no end date (zeros, no NaN). **Checkpoint first:** render the filter on the development store and compare with the store time zone; the Shopify `date` filter page does not state the time zone used for a text input. If the filter does not read the text in the store time zone or rejects the format, stop and report; the fallback is a strict `YYYY-MM-DD HH:MM:SS` parser in JS (visitor local time, as today). The ended state stays zeros (accepted).
3. R3 countdown width. `sections/promotion-countdown.liquid` `{% stylesheet %}`: the digit size is capped by the timer's available width (container query units, already used in `feature-tabs` and `routine-showcase`, else viewport units), keeping 36px and 120px as floor and ceiling.
4. R4 video focus. `assets/video-banner-external.js`: after `playing` turns true, focus moves to the inserted iframe on the next tick; `sections/video-banner.liquid` only if the iframe needs an `x-ref`.
5. R5 comparison drag. `sections/before-after-comparison.liquid` and `assets/before-after-comparison.js`: pointer events (`pointerdown`, `pointermove`, `pointerup`, `pointercancel` with pointer capture) instead of the mouse and touch pairs, and `touch-action: pan-y` on the drag area, so horizontal drags move the slider and vertical swipes scroll; the keyboard handling and the reduced-motion sweep stay.

Nothing else; any further change, stop and report.
