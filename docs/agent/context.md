## Plan 6-F1: page frame (width and screen height)

**Status:** recorded, **not authorized**. Review tier: **Ask**. It changes validator wiring (`lint-theme.js`, its tests), Liquid stylesheets in five sections and the CSS reference.

### Outcome

The page frame becomes the single owner of page width and the one-screen height unit, the way the JS runtime owns module loading. Inner layers consume what the frame provides and never recompute it. **Nothing on the storefront moves:** every computed column and content box is identical before and after. The visual tuning belongs to the calibration and polish batches.

### Why (our reasoning, 2026-10-07)

- **The gap was ownership, not mechanism.** The frame already had the tools (`container-page`, `section-frame` `width`, height kinds), but no rule said who owns what.
    - Sections recomputed the page inset themselves: `featured-product` until `355851f`, and `ritual-steps` still does.
    - Four sections write their own screen heights.
    - The same three-track grid is defined twice (`.shopify-section` in `assets/base.css` and `container-page` in `tailwind/tailwind.utilities.css`).
    - Each gap let a section quietly break the page margins, which the user then had to catch by eye.
- **Layers like the JS module graph:** tokens → page frame → section frame → section interior. The interior's grid or flex is the section's own business; width and the one-screen unit are not.
- **Enforced only where a rule is cheap to check and has few legitimate exceptions.** Everything else is written down as guidance, because a lint with a long exception list is noise.
- **Experience consulted (not authority):** the breakout grid with named lines (Ryan Mulligan); parent-owned composition and named exceptions (CUBE CSS, Every Layout); content-growing covers (Every Layout). Horizon centralises its page grid too, but it allows full-width content, and our background-only rule is our own decision. Sources: `C:/Users/Joey/AppData/Local/Temp/ceylune-css-spec-sources.md`.

### Rules this batch establishes

| Rule | Kind | Check |
| --- | --- | --- |
| One page-grid track list with named lines `full` / `content`, used by `.shopify-section` and `container-page` | Enforced by structure | A1 |
| Liquid files (`sections/`, `snippets/`, `blocks/`) never read `--page-width` / `--page-margin`; custom grids use the frame token `--page-inset` | **Enforced** (`lint:theme` `page-token-scope`) | A3, A5 |
| A one-screen height is written `var(--screen-height)`, never a literal `100svh` / `100vh` / `100lvh` in Liquid files | **Enforced** (`lint:theme` `screen-height-literal`) | A4, A5 |
| `section-frame` `width: 'full'` only in allowlisted sections, each with a reason; elsewhere content stays in the page grid | **Enforced** (`lint:theme` `frame-full-allowlist`) | A5 |
| Full-width sections keep text and controls on the `content` column (only backgrounds and named media span) | Guidance + verifier checklist | A6 |
| Fractional viewport units inside a section's own scroll choreography (for example `ritual-steps` offsets), and `dvh` caps on overlays, stay section or overlay business | Guidance | — |
| Section height defaults to content; screen heights only for hero, scroll stages, and media-led two-column sections | Guidance | — |

**`full` allowlist and reasons:**

| Section | Why it spans |
| --- | --- |
| `slides-show` | slide media behind content |
| `routine-showcase` | stage background |
| `article`, `blog` | hero media behind content |
| `main-page-about` | image behind content |
| `ritual-steps` | stage background; content inset by `--page-inset` |
| `promo-bannder` | edge-to-edge panel media; text alignment to be checked in the polish pass |
| `google-map` | the map is the content (named exception) |

### Implementation surface

- `assets/base.css`:
    - frame tokens on `:root`, defined once:
        - `--page-grid-columns` (named lines, the same tracks as today);
        - `--page-inset` (the existing `max(var(--page-margin), calc((100% - var(--page-width)) / 2))`);
    - `.shopify-section` uses the tokens; children default to `grid-column: content`, and `.full-width` uses `grid-column: full`.
- `tailwind/tailwind.utilities.css`: `container-page` uses `--page-grid-columns` and `grid-column: content`.
- `tailwind/tailwind.input.css`: `--screen-height: 100svh`; `--section-stage-min-height: var(--screen-height)`.
- `assets/tailwind.output.css`: regenerated by `npm.cmd run build:tw` only.
- `sections/ritual-steps.liquid` (`{% stylesheet %}` only): two formulas → `var(--page-inset)`; `100svh` → `var(--screen-height)`.
- `sections/featured-product.liquid`, `sections/promo-bannder.liquid`, `sections/routine-showcase.liquid` (`{% stylesheet %}` only): `100svh` → `var(--screen-height)` inside the existing formulas. Values stay the same.
- `sections/product.liquid`: the `desktop_media_max_height` value `'100svh'` → `'var(--screen-height)'`.
- `.agents/skills/check-theme-architecture/scripts/lint-theme.js` (and `lib/` if rules live there): the three rules above.
- `.agents/skills/check-theme-architecture/scripts/theme-architecture.test.js`: one pass and one fail case per rule.
- `.agents/skills/check-theme-architecture/SKILL.md`: rule list.
- `docs/references/style-system/css-architecture.md`, Page frame section:
    - the layer order and what each layer owns;
    - the tokens;
    - the rules table above (enforced vs guidance);
    - the `full` allowlist.
- Records: `docs/agent/context.md`, `docs/agent/board.md`.

**Out of scope:**
- unifying the media-led formulas (`featured-product`, `routine-showcase`) onto one value; that changes visuals and moves to calibration;
- section CSS `@layer` (next batch);
- spacing, type, colour and breakpoint tokens;
- any merchant configuration.

### Deviations from the step 1 conclusion (user to accept with authorization)

1. **Height enforcement is narrowed.** The conclusion banned all `vh` / `svh` / `dvh` in section stylesheets. The repository has about 30 legitimate uses: scroll choreography offsets in `ritual-steps` (`11svh`, `4svh`, …), overlay caps (`image-lightbox`, `product-media-modal`, `search-predictive-panel`, header menu `dvh`), and the `article` / `search` heroes. A blanket ban would need a long exception list. This batch enforces only the one-screen literal.
2. **The media-led sections keep their formulas** (only the unit becomes the token). Unifying them changes visuals, so it moves to calibration.
