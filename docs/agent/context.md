## Plan 6-S13: mobile card rail for ritual-steps and routine-showcase

**Status:** direction accepted by the user (2026-10-07, board "Mobile card pattern, decided"). It runs from an external execution prompt; handing the prompt over is the user's authorization. Review tier: **Ask** (markup, JS, external prompt). The user checks the look on a phone.

### Outcome

Below 1024px, `ritual-steps` (both styles) and `routine-showcase` show the same mobile pattern:
- one card per screen with page-margin gutters, capped at 30rem and centred (tablets);
- no visible scrollbar, and all cards as tall as the tallest;
- swipe left and right, with dots below that follow the swipe and jump on click.

Style A follows its design. Desktop (1024px and up) is unchanged.

### Evidence (coordinator, code read, 2026-10-07)

- **`routine-showcase`:**
    - `.routine-showcase__mobile-rail` is `overflow-x: auto` with snap and a visible scrollbar;
    - slots are `flex: 0 0 78%`, so the next card peeks;
    - `.routine-showcase__mobile-card` does not fill its slot, so heights differ;
    - there are no dots and no mobile JS. `assets/routine-showcase.js` runs autoplay on desktop only.
- **`ritual-steps`:**
    - **Rail and dots:** `.ritual-steps__mobile-rail` has the same scrollbar problem, with slots at `flex: 0 0 88%`. Dots already exist (`.ritual-steps__dots`). `assets/ritual-steps.js` tracks the active card with an IntersectionObserver rooted on `[data-ritual-mobile-rail]`, and `_scrollMobileToIndex` scrolls the rail on dot click.
    - **Style A missing image:** style A's mobile card renders `.ritual-steps__oval-scene--mobile`, but a later top-level rule `.ritual-steps__oval-scene { width: auto; height: 76%; max-width: 92%; max-height: none; aspect-ratio: 0.7; }`, meant for desktop and outside the 64rem query, likely collapses it (user screenshot: no image on mobile). Confirm in the browser before fixing.
    - **Duplicate heading:** style A on mobile shows the section heading above the rail and again inside each card (`.ritual-steps__mobile-heading-copy`, `aria-hidden`). The design shows it once, inside the card.
- **Style A design** (user image, mobile): oval image (rotated ring, sparkle), heading, step badge, step title, text, link with arrow, dots below.

### Approach

1. **Shared pattern, one owner.**
    - **CSS:** the rail CSS becomes shared component classes in `tailwind/tailwind.components.css`, for example `.card-rail`, `.card-rail__slot` and `.card-rail__dots`. The CSS layer may use `--page-margin`.
        - Rail: `display: flex`, `overflow-x: auto`, `scroll-snap-type: x mandatory`, hidden scrollbar (`scrollbar-width: none` plus `::-webkit-scrollbar { display: none; }`), `padding-inline` and `scroll-padding-inline` equal to the page margin.
        - Slot: `flex: 0 0 min(100% - 2 × page margin, 30rem)`, `scroll-snap-align: center`, `display: flex`.
        - Card: fills the slot height (`flex: 1`).
        - When all cards fit, keep them centred.
    - **JS:** one module drives the dots (active index from an IntersectionObserver on the rail; click scrolls to the card; `aria-current` on the active dot). Preferred: move the existing ritual-steps mobile logic into a shared module `assets/card-rail.js` (registered in the import map in `snippets/scripts.liquid`, mounted by `data-module-id`) and use it in both sections. If ritual-steps' dots are entangled with its desktop carousel logic, keep ritual's JS, give `routine-showcase` the shared module, record why, and leave ritual's migration as a follow-up.
    - **Dots:** match the existing ritual dots look. Use buttons with accessible names from locale keys.
2. **`ritual-steps` style A on mobile:**
    - fix the oval scene sizing on mobile, by scoping the desktop rule to the 64rem query or overriding it under `--mobile`, so the image shows as in the design;
    - show the heading once: keep the section `h2` for the outline but hide it visually on mobile, and keep the in-card copy.
3. **`ritual-steps` style B:** content unchanged; adopt the shared rail.
4. **`routine-showcase`:** content order unchanged (image above content); adopt the shared rail, add dots.

### Acceptance checks

- **A1 Pattern.** Chrome DevTools MCP on the dev theme, at 390 and 768, for `ritual_steps_sticky`, `ritual_steps_carousel` and `routine-showcase`:
    - the rail computes `scrollbar-width: none` and shows no scrollbar;
    - exactly one card is fully visible;
    - at 768 the card width is at most 480px and centred;
    - every card in a rail has the same `offsetHeight`;
    - the page has no horizontal scroll (`scrollWidth <= clientWidth`).
- **A2 Dots.**
    - The number of dots equals the number of cards.
    - After a programmatic `rail.scrollTo` to card 2, the second dot has `aria-current="true"` within 1s.
    - Clicking dot 3 brings card 3 into view.
    - Keyboard: Tab reaches the dots, and Enter or Space activates them.
- **A3 Style A design.**
    - **Visible:** at 390, the mobile card shows the oval image (`.ritual-steps__oval-clip` has a non-zero height), then the heading, badge, step title, text and link, in that order.
    - **Heading once:** the section heading is not visible but is still in the accessibility tree as an `h2`.
- **A4 No JS.** With JavaScript disabled at 390, each rail still scrolls and snaps, and the first card is complete.
